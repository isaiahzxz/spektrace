# Dashboard announcements

Open Settings → Platform announcements, or use Edit beside Announcements in the sidebar. Choose Product update, Platform issue, or Maintenance; enter a title and message; then Publish announcement. Save draft & hide removes it from the sidebar and retains the draft for editing. Hidden draft text is not sent to workspace viewers. Published text appears across all workspaces after refresh or navigation. One current announcement is supported; no announcement history, scheduled publishing or notification broadcast is implied.

Only the verified account whose Better Auth user ID exactly matches the single private server variable SPEKTRACE_PLATFORM_OWNER_ID may publish. There is no unsigned local-mode publishing exception. Until account sign-in and the owner ID are configured, publishing controls are hidden for everyone. Regular workspace owners cannot publish platform-wide notices. Requests require the configured origin and an authorized workspace session. User IDs and credentials are never editable through this form.

This single-server MVP stores the board in work/platform-announcements.json using validated text and atomic file replacement. An operator may set SPEKTRACE_ANNOUNCEMENTS_FILE to a persistent private file outside public/. Back up this file if retaining the draft matters. Ephemeral or multiple-server deployments require shared persistent storage before relying on announcements. The synthetic review sets its own file inside its disposable review directory and never changes the normal board. No announcement sends Slack or email automatically.

The Overview uses scoped stored records. Call/finding/outcome metrics use a rolling 24-hour received window; latest rows and integration capture status use retained history. The ring shows scopes with calls recorded among up to the first 100 known scopes, not uptime. Stored finding counts are distinct from latest validated finding rows. Captured calls never imply complete traffic; explicit identifier linkage never establishes causation.
